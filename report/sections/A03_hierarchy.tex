\section{Hierarchical modelling and the scene graph}
\label{sec:hier}
\here{2}
Articulated objects are trees. Moving a node moves everything below it, because each world matrix is the
parent's world matrix times the local one. Animation then only changes a few local angles.
\begin{equation}
W_{\text{node}} = W_{\text{parent}}\,M_{\text{node}} = M_{\text{root}}\,M_1\,M_2\cdots M_{\text{node}}
\label{eq:world}
\end{equation}
\begin{itemize}
\item Depth-first traversal: a parent's $W$ is ready before its children use it; one matrix product per node, $O(n)$ for $n$ nodes.
\item A group node has a matrix and no mesh; a pivot is a group whose origin is the hinge (Eq.~\eqref{eq:pivot}).
\end{itemize}
\begin{lstlisting}[language=C++,caption={The whole scene-graph update: Eq.~\eqref{eq:world} applied recursively (\code{src/scene/Scene.cpp: updateNode}).}]
void updateNode(SceneNode& node, const Mat4& parentWorld, float explode) {
    Transform t = node.local;
    if (explode > 0.0f && node.explodable) t.translation = t.translation * (1.0f + 0.7f * explode);
    node.world = parentWorld * t.matrix();                  // W = W_parent * T * Ry * Rx * Rz * S
    for (auto& c : node.children) updateNode(*c, node.world, explode);
}
\end{lstlisting}

The camera and the searchlight hang under two gimbal groups. The visual-servo controller writes only their two
angles, and Eq.~\eqref{eq:world} carries the lamp, its light direction and the camera frame along. Section~\ref{sec:decomp}
pulls every design apart along this tree: in Figure~\ref{fig:d-autonomous_uav} the sub-assemblies (motor mount with
rotor, gimbal with camera) move out as blocks before their parts separate.

\textbf{Limitation.} The world matrices of all \nLeaves{} parts are recomputed on the \ab{497}{CPU} every tick, static
buildings included. That is cheap here (the simulation step takes a few milliseconds); a larger scene would cache static
subtrees.
