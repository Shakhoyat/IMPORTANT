# F3 notes: Excel sheet snapshots for the report

Regenerate: `uv run --with openpyxl --with pillow python tools/xlsx_snapshot.py [--only <name-prefix>]` (about 30 s) ->
`report/sheets/*.png` (192 dpi-equivalent) + `report/sheets/captions.json` (key = image name without .png; fields file, sheet, range,
caption, concept, formula_bar, rows_shown, columns_shown, px).

Key facts
- The workbook written by build_workbook.py has NO cached formula values (openpyxl never calculates). tools/xlsx_snapshot.py
  therefore contains a small lazy Excel evaluator (IF, INDEX/MATCH, COUNTIF(S), SUMIFS, SUMPRODUCT, QUARTILE, ...) and shows the values
  Excel would show. Check: Excel M vs code max error recomputed by it = 2.4e-5 (matches the workbook's own verdict), 0 errors on all
  sheets except sheet 11 B18 (real STALE flag: benchmark scene 805 parts vs 4549).
- The workbook has no MMULT: sheet 4 builds M = T x R x S with explicit sum-of-products formulas (4x4 blocks in the worked example
  AY4:BQ29); the lab primitives carry no UV, so the vertex table is x, y, z, nx, ny, nz.
- The workbook is a snapshot of build time: 194 tests (build/test_results.json now has 169 + visual/behaviour checks).
- Renderer features: headers, gridlines, fills, fonts, borders, merges, alignment, number formats, widths / heights, conditional
  formats, formula bar with selected-cell outline, embedded images, bar / scatter charts (incl. log axis). Fonts are DejaVu (Calibri is
  absent), scaled to 85 %; numbers that do not fit shrink instead of "####"; rows without explicit height auto-fit wrapped text.
